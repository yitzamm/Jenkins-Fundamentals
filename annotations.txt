JENKINS IMG WITH BLUE OCEAN PLUGIN FOR CI/CD

1. Pull the latest Jenkins LTS image: docker pull jenkins/jenkins:lts
2. Run a temp Jenkins container: docker run -d --name jenkins-temp jenkins/jenkins:lts
3. Install the Deep Ocean plugin inside the container: docker exec jenkins-temp jenkins-plugin-cli --plugins blueocean docker-workflow
4. Save the container as a new img: docker commit jenkins-temp myjenkins-blueocean:lts
5. Remove the temp container: docker rm -f jenkins-temp
6. Create a network for Jenkins: docker network create Jenkins
NOTE: Verify existing networks with docker network ls; verify existing images with docker images; verify running containers with docker ps
7. Run the container:

docker run --name jenkins-blueocean --restart=on-failure --detach `
  --network jenkins --env DOCKER_HOST=tcp://docker:2376 `
  --env DOCKER_CERT_PATH=/certs/client --env DOCKER_TLS_VERIFY=1 `
  --publish 8080:8080 --publish 50000:50000 `
  --volume jenkins-data:/var/jenkins_home `
  --volume jenkins-docker-certs:/certs/client:ro `
  myjenkins-blueocean:lts

NOTE: The backtick is equivalent to the back slash in Linux/macOS

SET UP A CLOUD-LIKE ENV 

>> CREATE A DOCKER PROXY <<

docker run -d --name docker-proxy --restart=always `
-p 127.0.0.1:2376:2375 `
--network jenkins `
-v /var/run/docker.sock:/var/run/docker.sock `
alpine/socat `
tcp-listen:2375,fork,reuseaddr unix-connect:/var/run/docker.sock

NOTE: This command is a Docker socket proxy. It lets another container (like Jenkins) talk to the Docker daemon on your host machine [Jenkins container <- TCP connection -> Socat proxy container <- Unix socket -> Docker daemon on host]. This way Jenkins can run Docker commands without running Docker inside Jenkins per se.

This new container will act as a Docker API bridge. Jenkins pipelines often run commands like: docker build, docker run, docker push. But Jenkins itself is inside a container, so it needs a way to reach Docker. The proxy provides that.

Verification command >> docker inspect docker-proxy

In Jenkins "New cloud" settings insert the IP address from the inspection into the Docker Host URI field: tcp://172.18.0.3:2375
Check the "Enabled" button and test the connection

CREATE A JENKINSFILE

Original:
stage('Build') {
            steps {
                echo "Building.."
                sh '''
                cd myapp
                pip install -r requirements.txt
                '''
            }
        }

ERROR: Alpine Linux blocks this because of PEP 668 (externally managed environment)

TS:
python3 -m venv venv (creates an isolated Python environment)
. venv/bin/activate (tells the shell to use that environment)

Updated to:
stage('Build') {
            steps {
                echo "Building.."
                sh '''
                cd myapp
                python3 -m venv venv
                . venv/bin/activate
                pip install -r requirements.txt
                '''
            }
        }

ERROR: ModuleNotFoundError

TS:
stage('Test') {
            steps {
                echo "Testing.."
                sh '''
                cd myapp
                python3 hello.py
                python3 hello.py --name=Brad
                '''
            }
        }

NOTE: The venv folder still exists in the workspace, but the environment activation does not carry over.
